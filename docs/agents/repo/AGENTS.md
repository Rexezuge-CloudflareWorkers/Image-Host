# Image-Host — Working In This Repository

Scope: the workspace layout, the commands, the layer rules, and the gates a change has to pass. Parent index: [`../../../AGENTS.md`](../../../AGENTS.md).

Nothing here is a design decision — those live in the area guides. This is the mechanical part: what exists, what runs it, and what refuses to merge.

## The workspace

`pnpm-workspace.yaml` globs `apps/*`, `packages/*`, and `test` → **8 projects**:

| Layer | Projects                                   | May import                                                                             |
| ----- | ------------------------------------------ | -------------------------------------------------------------------------------------- |
| 0     | SDK `@rexezuge/shared`, `@rexezuge/errors` | nothing                                                                                |
| 0     | `shared`                                   | nothing                                                                                |
| 2     | `backend-data`                             | layer 0 + SDK D1                                                                       |
| 3     | `provider-clients`                         | layer 0 (Telegram Bot API — the only external provider)                                |
| 3     | `backend-services`                         | layers 0, 2, 3; never `apps/*`                                                         |
| app   | `api`                                      | layers 0–3; **not** `provider-clients`, **not** `backend-data/dao` (type-only allowed) |
| app   | `web`                                      | the browser                                                                            |
| test  | `test`                                     | everything                                                                             |

There is no layer 1 and no layer 4 by design: this repository has no separate runtime-adapter layer (configuration reading sits in `backend-services`, which is a layer 3) and nothing between `backend-services` and the entrypoints.

### The layer rules are enforced unevenly, and the gaps are worth knowing

`no-restricted-imports` in `eslint.config.mjs` is generated by `defineRepoLintConfig` for the four named package layers, plus one `extraLayers` entry for `apps/api`. **There is no block for `apps/web`** — that row is convention, not enforcement, so a wrong import there fails nothing. If you add a package, add its block with it rather than after.

The `apps/api` entry is a **single merged block** for two reasons, both load-bearing:

- Two entries for one directory install only the last one, so the DAO ban or the provider ban would be silently dropped.
- `allowTypeImports` is a property of a **group**, not of a layer. Keeping them separate would either permit a `provider-clients` value import or forbid a DAO type-only import.

The DAO ban is scoped to `@image-host/backend-data/dao` rather than the whole package, because `apps/api` legitimately imports `backend-data/presenters` — which is not a DAO.

`packages/shared` is layer 0, so its schema module imports constants **relatively** (`../constants`). Reaching for `@image-host/shared/constants` from inside the package is the boundary rule reporting on a self-import.

## `scripts/` and `functions/` are not workspace packages

`pnpm run typecheck` reaches them through `typecheck:scripts` and `typecheck:functions`, so a new directory there needs its own script or nothing checks it at all. `functions/[[path]].ts` is the Cloudflare Pages entrypoint that proxies to the worker over the `API_WORKER` service binding, which is the one place the two wrangler templates are coupled. `scripts/README.md` documents the entrypoint-vs-module convention (`#!` files export nothing, so `unicorn/no-exports-in-scripts` leaves them lintable).

`test/` **is** a workspace project, so `pnpm -r typecheck` and `pnpm run lint` both reach it. It has its own `node_modules`, which is why both Vitest projects re-list `**/node_modules/**` in `exclude` — naming `exclude` at all replaces Vitest's defaults rather than adding to them.

## Commands

```bash
pnpm install
pnpm run checks          # checks:fast, then coverage, then integration
pnpm run checks:fast     # typecheck + lint + god-files + migrations + SPA shell
pnpm run typecheck       # -r, plus scripts/ and functions/
pnpm run lint            # eslint --fix --quiet
pnpm run check:god-files # 300 warn / 400 error
pnpm run validate:migrations   # read-only; refuses an edited or unlocked migration
pnpm run migrations:lock       # records a NEW migration; never re-hashes an applied one
pnpm run verify:spa-shell      # needs `pnpm --filter @image-host/web build` first
pnpm run test
pnpm run test:coverage
pnpm run test:integration
pnpm --filter @image-host/web run build  # the only build script
pnpm run typegen         # wrangler types from apps/api/wrangler.template.jsonc
pnpm exec wrangler dev --config ./wrangler.jsonc
```

Plain `pnpm` is canonical. `pnpm --filter @image-host/web run build` resolves to exactly one thing, the SPA's `vite build`, so `pnpm run build` "succeeding" can still mean the embedded shell is the stub `postinstall` wrote. `verify:spa-shell` is the check for that, and it is in `checks:fast`.

`pnpm run lint` sets `NODE_OPTIONS=--max-old-space-size=6144` itself, because type-aware ESLint exhausts the default heap here. Prefix any _manual_ `eslint`/`vitest` invocation with the same flag. `test/package.json` sets its own 4 GB for the same reason: `test/tsconfig.json` is the only project that pulls in every package at once, and tsc emits no `error TS` line when V8 kills it, so the failure is indistinguishable from a clean run.

## The gates

**Aggregate coverage is `83 / 63 / 84 / 85`** (statements / branches / functions / lines), against a measured 83.77 / 64.45 / 85.51 / 86.08. This is a _starting_ ratchet — raise it as coverage improves, and never lower it to make CI green.

Read the report together with `pnpm run test:integration`: the node project reports `packages/backend-data/**` as thinly covered because the DAOs' real behaviour (`LIKE` escaping, `LIMIT ? OFFSET ?`, `meta.changes`) is exercised in the workerd suite instead, and that coverage is not reported by `test:coverage`.

There is **no per-file floor** (`check:coverage-floor` is not ported — there is no kit equivalent). When one is added, pin the auth boundary, the share-link read, and the ownership-scoped writes: an aggregate can be met while one of those rots.

**The god-file guard** is 300 warn / 400 error, counting `split('\n').length`. It skips `node_modules`, `dist`, `.wrangler`, coverage directories, `.git`, `generated/`, test files, `*.d.ts`, and every `.md`/`.json`/`.sql`.

**`validate:migrations` is read-only and fails on an edit.** D1 records applied migrations by _filename_, so a file that has run is skipped silently by every later `wrangler d1 migrations apply`: the deploy succeeds, fresh databases pick up the edited statements, production keeps the old schema. `migrations/migrations.lock.json` records a SHA-256 per file. This repository has **no squash file**, so every migration is immutable — there is no baseline exemption. After adding a migration: `pnpm run migrations:lock`.

**`verify:spa-shell` is a precondition gate, not a convenience.** A fresh checkout has neither `apps/web/dist/` nor `apps/api/src/generated/`; `postinstall` writes a deliberately minimal stub so `tsc` can resolve `SPA_HTML`. Verifying without building cannot pass. See [`../runtime/AGENTS.md`](../runtime/AGENTS.md) for why the Vite plugin takes an explicit `root`.

## `@rexezuge/tooling`: what is adopted

| Adopted                                       | Notes                                                                                                                             |
| --------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------- |
| `defineRepoLintConfig`                        | Needs `extraIgnores: ['!scripts/**']` — see the header of `eslint.config.mjs`.                                                    |
| `defineRepoVitestConfig`                      | One file, two projects (node backend + jsdom web).                                                                                |
| `defineIntegrationVitestConfig`               | Plus the workerd plugin/pool, passed through untouched by design.                                                                 |
| `defineWebViteConfig` + `spaShellEmbedPlugin` | The plugin's default `root` is `process.cwd()`, which `pnpm --filter` sets to `apps/web`. `vite.config.ts` pins an absolute root. |
| `createPagesProxy`                            | Strictly better than a hand-rolled copy: it strips every client-settable forwarding header.                                       |

Nine files under `scripts/` are **byte-identical** to AWS-AccessBridge's, and `scripts/README.md` records which and why. Re-deriving them here would be the drift the family convergence exists to prevent.

## What is generated, and what is not

| Path                                  | Generated by                                           | Tracked                                                                                  |
| ------------------------------------- | ------------------------------------------------------ | ---------------------------------------------------------------------------------------- |
| `worker-configuration.d.ts`           | `pnpm run typegen` (also `postinstall`)                | no — gitignored; the binding source of truth is `packages/backend-services/src/env.d.ts` |
| `apps/api/src/generated/spa-shell.ts` | the web build                                          | no — gitignored, verified by `verify:spa-shell`                                          |
| `apps/web/dist/`                      | the web build                                          | no                                                                                       |
| `migrations/migrations.lock.json`     | `pnpm run migrations:lock`, on adding a migration only | yes                                                                                      |
| `wrangler.jsonc`                      | `scripts/deploy/prepare-wrangler-config.ts`            | no — gitignored                                                                          |
| `coverage/`                           | `pnpm run test:coverage`                               | no                                                                                       |

A binding must appear in four places: `packages/backend-services/src/env.d.ts`, `apps/api/wrangler.template.jsonc`, the generated `worker-configuration.d.ts`, and `ServiceEnv`. A binding present in three of the four is the failure mode worth avoiding.

## CI

`.github/workflows/continuous-integration.yml` runs **one job per check**, so a red pipeline names its failure rather than arriving inside a typecheck log: `typecheck`, `lint`, `migrations`, `god-files`, `unit-tests`, `integration-tests`, `build-web`, `spa-shell`. `spa-shell` builds the SPA itself rather than depending on `build-web` — that costs a second Vite build per run and buys a failure that says "the served shell is wrong". `continuous-deployment.yml` deploys the worker and the Pages target.

Six `.github/` files are byte-identical to AWS-AccessBridge's: both composite actions, `dependabot.yml`, `.version`, `backup-main.yml`, `scheduled-version-update.yml`. `upstream-sync.yml` differs by one line (the upstream repository name). The job names are the documentation of what each one proves.

`backup-d1.yml` is **not** ported — it is AWS-AccessBridge-local rather than kit-supplied, and it needs eleven backup scripts. D1 here holds image metadata, not credentials; add it when the metadata is worth nightly off-site copies, and port the scripts then rather than carrying dead workflow references now.

## Adding a directory

A new `apps/*` or `packages/*` directory needs a `package.json` with a `typecheck` script, a `tsconfig.json`, and a layer decision — which is a decision about what it may import, so add the `no-restricted-imports` block with it. A new `scripts/*` or `functions/*` directory needs its own `typecheck:*` script, since neither is in the workspace. Either way, add the area to the root [`AGENTS.md`](../../../AGENTS.md) index and write the guide in the same change.
