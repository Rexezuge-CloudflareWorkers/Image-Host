# Image-Host — API Worker

Scope: `apps/api/**`. Parent index: [`../../AGENTS.md`](../../AGENTS.md). Runtime and bindings: [`../../docs/agents/runtime/AGENTS.md`](../../docs/agents/runtime/AGENTS.md).

- `src/index.ts` — `fetch` via `ImageHostWorker`.
- `src/workers/ImageHostWorker.ts` — Hono routes, **no Chanfana file-routing**. `createApp()` is a factory, not a module singleton, so a test gets an isolated app and the middleware ordering is visible in one place. Its default export carries both surfaces: `fetch` and `scheduled`.
- `src/workers/scheduled.ts` — the cron surface: the daily `image_views` retention prune, wired to `triggers.crons` in `apps/api/wrangler.template.jsonc`. A plain `scheduled` export rather than a Durable Object alarm: the prune is periodic, global and idempotent — overlapping runs are harmless — whereas the family reserves alarms for entity-scoped deferred work (see `AWS-AccessBridge`/`Edge-Git`). It resolves `ViewLogRetentionService` through `createRequestScope(env)`, like a route resolves its services, and lets errors propagate so a failed run is visible rather than swallowed.
- `src/types.ts` — `AppEnv` / `AppVariables` / `ImageHostContext`. Named context properties, so `c.get('Scope')` is typed and a typo is a compile error.
- `src/middleware/` — `securityHeaders` (`*`), `scopeMiddleware` (`*`), `noStoreHandler` + `csrfProtection` + `userAuthentication` (`/user/*`).
- `src/errors/routeHelpers.ts` — `handle()` wraps every route body; `app.onError` covers middleware and the catch-all. No path reaches the client that skips the mask.
- `src/generated/spa-shell.ts` — generated by the web build; do not edit.

## Two surfaces, and the split is the security design

- **`/user/*` is the human surface** and sits behind Cloudflare Access: upload, management, and the console.
- **Everything else is public.** `GET /i/:slug` has to work in an `<img src>` with no cookie, no header and no session — that is what makes a link sharable — and `GET /` serves the SPA shell so an anonymous visitor sees a landing page rather than a login redirect.

`GET /user` redirects to `/user/` preserving the query string. Navigating there is what triggers the Zero Trust login flow. `/` does **not** redirect: the client decides what to render.

## Auth

`ImageHostAuthService` resolves in this order, each step a fallback for a _different_ deployment shape rather than a preference:

1. **`DEMO_MODE`** — a read-only showcase with a fixed identity.
2. **`DEV_AUTH_EMAIL`** — `wrangler dev` and the integration suite. Read before verification and **refused under `production`**, or a value promoted from `.dev.vars` would authenticate every caller as that address.
3. **JWT** (`jose` `jwtVerify` + `createRemoteJWKSet`) when `TEAM_DOMAIN` _and_ `POLICY_AUD` are both set.
4. **`ctx.access.getIdentity()`** — the same-account one-click Access case.
5. Last resort: re-run the JWT verify without config, which fails on missing config.

Two details are load-bearing, not stylistic:

- **JWKS is memoized per team domain, process-wide.** A fresh `createRemoteJWKSet` per request re-fetches `/cdn-cgi/access/certs` on every verification, putting the team domain's latency on the hot auth path and making an Access outage an outage of every authenticated request — including ones a cached key would have verified.
- **The `jose` detail is logged; the client gets a generic `UnauthorizedError`.** `jose`'s message names the expected issuer and audience and can quote the cert-fetch endpoint.

**Never trust `Cf-Access-Authenticated-User-Email`.** It is a claim the client sent. Identity comes from `ctx.access` (platform-verified) or a verified assertion. The constant is deliberately absent from `packages/shared/src/constants/Headers.ts` so a grep finds its absence.

## CSRF

`csrfProtection` rejects cross-origin mutations on `/user/*`. A Zero Trust session cookie is sent automatically by the browser, which is what makes it a CSRF target — and Cloudflare Access cookies are `SameSite=None` by design, because they must survive the cross-site redirect the login flow performs. The cookie alone is not the protection.

`Origin` is consulted, falling back to `Referer`, and **an absent _both_ is rejected** rather than allowed: a browser always sends one of the two for a cross-origin mutation, so their joint absence means the request did not come from a browser.

## Error envelope

`{ "Exception": { "Type": "...", "Message": "..." } }` throughout, from `@rexezuge/errors`' `ServiceError.toErrorResponse()`. A non-exposed error (5xx) has its message substituted at that layer, so a `DatabaseError`'s internals never reach the client.

`routeHelpers.toErrorResponse` logs a 5xx at `error` and a 4xx at **`warn`** — a 404 on somebody's stale link is normal traffic, and logging it at `error` trains everyone to ignore the error log.

## Notable route decisions

**The share body is streamed, not buffered.** `ImageService.download` returns the upstream `Response` with its body intact. Reading it into an `ArrayBuffer` here costs the isolate its heap and shows up as Workers error 1102 under exactly the concurrent load this route exists for.

**`Content-Type` comes from the stored row**, not the upstream response. Telegram serves documents as `application/octet-stream` regardless of content, so trusting the header would make every image download instead of display. `Content-Disposition` is `inline`, not `attachment` — the predecessor set `attachment`, which made every shared image download rather than render.

**The slug is shape-checked before any database round-trip.** `makeSlug` emits `[A-Za-z0-9]{16}`; a segment that cannot be one we generated is a 404 whatever the query returns, so there is no reason to ask — and the length bound stops a 100 KB path segment being bound into a prepared statement.

**The catch-all serves the shell only for `/user/*`.** `/i/` is an exact registered route and can never reach it, but the guard is explicit rather than relying on that: a catch-all that fell through would answer a dead share link with a 200 and an HTML page.

**Routes never import `provider-clients` or a DAO.** The lint boundary forbids it (type-only for DAOs), and `ImageService` exposes `download` / `recordView` so there is a supported way in. The `Container` is the only place a `TelegramClient` is constructed, under a private key absent from the public token table — so the boundary holds by construction, not convention.

**`scope.get(...)` returns a promise.** Reading the bot token is an `await` on a Secrets Store binding, so the container resolves services asynchronously — `await getScope(c).get(Tokens.ImageService)`. It caches the _promise_, so a factory runs once and concurrent callers share one result; a rejection is cached with it, which is right because the binding will still be absent on the next request. `getScope(c)` itself stays synchronous: it only reads the context.
